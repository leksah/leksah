Leksah × Claude: Integration Improvement Plan

What the agent-IDE field (Orca, Herdr, Conductor, Sculptor, Nimbalyst, claude-squad, …) offers, where leksah already leads, where it lags, and a staged plan that fits leksah's tmux-backed architecture. Drafted July 2026.

Executive summary

A whole product category ("Agent Development Environments") has formed around exactly what leksah already is: a workbench that hosts real terminal agents next to an editor, git views and notifications. Leksah's foundations are unusually strong — real tmux panes (herdr's headline feature), remote (ssh) projects and terminals (Orca's SSH mode), attention/bell routing with spoken alerts, per-session tree nodes, and an embedded browser pane in progress (Orca's embedded Chromium). What the field has that leksah lacks clusters into four things:

  • Semantic agent state — every serious tool shows idle / working / blocked / done per session, at a glance.
  • Worktree-isolated parallel sessions — the defining feature of Conductor, Orca and Crystal/Nimbalyst: one branch + checkout per agent task, with a review → merge → archive flow.
  • Diff review wired back to the agent — Orca's inline diff comments that are batch-submitted to the session.
  • The IDE as a tool surface for the agent — nobody does this well yet; leksah's LSP diagnostics + leksah-cmd socket make it a cheap, differentiating win (an MCP server).

Recommended top-3: (1) agent state detection + surfacing, (2) worktree-per-session with a review/merge flow, (3) a leksah MCP server so Claude can see diagnostics and drive the editor.

Tool-by-tool findings

Orca (onorca.dev) — "Agent Development Environment"

  • Fleet of parallel agents (Claude Code, Codex, OpenCode, 15+), each confined to an isolated git worktree; GitHub PRs/issues/Actions linked per worktree.
  • Inline markdown comments on diff lines, batch-submitted back to the agent — the standout review loop.
  • Ghostty-inspired terminal with infinite splits; VS Code-compatible editor.
  • Embedded Chromium per worktree with a "Design Mode" (click an element to inspect HTML/CSS) — the same direction as leksah's new browser pane.
  • SSH remote worktrees with auto-reconnect; notifications when an agent finishes or needs attention; account switching with usage/rate-limit and cost dashboards; iOS/Android companion mirroring live sessions.

Sources: onorca.dev, Orca review, dev.to review

Herdr — terminal-native agent multiplexer (Rust)

  • "tmux, but agent-forward": workspaces → tabs → panes, session persistence, detach/reattach, --remote ssh://… mode.
  • Zero-config agent state detection (process-name + output heuristics) → sidebar shows each pane's agent as idle / working / blocked / done. A dedicated Claude Code integration adds semantic state forwarding over a local socket and session restoration.
  • A socket API + agent skill so agents themselves can spawn panes/workspaces and organise their own work.

Sources: herdr guide, tecmint, claudekit

Prioritized proposals

1. Semantic session state Effort S–M

What: per-Claude-session state — working / blocked-on-approval / done / idle — shown as coloured badges on the workspace-tree Claude nodes, the Terminals tree, tab buttons and the flipper; plus "jump to next blocked session" (extend the existing CommandFocusAlert ordering: blocked > bell > activity).

How it fits: install Claude Code hooks (Notification, Stop, PreToolUse/permission) via a leksah-managed settings.json include that appends one JSON line per event to ~/.leksah/claude-state/<session>.jsonl (or writes a tmux window option — leksah already polls tmux options for @leksah_layout). The pane-tree poller picks it up; falls back to today's bell/activity heuristics for non-hooked agents — exactly herdr's two-tier design.

2. Worktree-per-session + review/merge flow Effort M

What: "New Claude Session in Worktree" (context menu on a project/dir): creates .worktrees/<task> + branch, runs the session there; the tree groups the worktree under the project with its PR/ahead-behind badges (already built); a per-session Review action shows git diff <base>...HEAD for that worktree; buttons for merge / PR (gh) / archive (remove worktree, prune branch).

How it fits: leksah already has directory projects ("Open Folder…" — a worktree is just a directory project), git polling, PR status via gh, and session-per-open tmux windows. The review pane can reuse the git-log/diff machinery; "send review comment" types into the session's tmux pane via the existing send-to-target plumbing (the same path as Send Error).

3. Leksah MCP server for Claude Effort M

What: expose leksah to Claude sessions as MCP tools: get_diagnostics (the Errors pane / LSP allLogRefs, scoped to the active project), open_file / reveal, active_selection, build (rebuild-self / project build with the parsed result), screenshot, hover (LSP hover at a position). Register it in the session's .mcp.json when leksah launches the session.

Why: nobody in the field feeds the agent live IDE state; leksah's LSP layer + leksah-cmd socket already have every primitive. Agents stop grepping for errors they could just ask for — a genuine differentiator.

How it fits: a small stdio-MCP shim binary (or a leksah-cmd mcp subcommand) that proxies to ~/.leksah/cmd.sock; the CmdServer grows the few missing queries (diagnostics dump exists in spirit via the Errors pane model).

4. Session browser + resume-any Effort S

Parse ~/.claude/projects/<dir>/*.jsonl (first user message = title, mtime, model, token totals) into the Claude tree node's children; double-click → claude --resume <id> in a new tmux window. Extends "Continue Last" to "continue any".

5. Per-session cost/usage Effort S

Sum usage records from the same transcript JSONL; show tokens/$ in the session node tooltip and the status bar for the focused session. (Orca-style dashboards later, if ever.)

6. Diff-comment → session loop Effort M

In the review pane of proposal 2, allow selecting diff lines and typing a note; leksah sends @file#L10-L20 <note> into the session (the Send Selection path). Orca's best feature, nearly free on leksah's plumbing.

7. Task queue (kanban-lite) Effort L

A pane of queued prompts per project; a queued card starts a worktree session (proposal 2) when a slot frees. Do after 1–3; Vibe Kanban's shutdown suggests the board alone isn't the product.

8. Plan-mode review surface Effort M–L

Detect plan-mode output (hooks / transcript) and render the plan markdown in a leksah pane with Approve / Revise buttons that type the response into the session. Pairs with AIDEN's "spec approval before coding" finding.

9. Browser pane ↔ session links Effort S

When an agent's terminal prints a localhost URL (the terminal-links JS already detects URLs), offer "open in browser pane" — ⌥ to open it as a split beside the session. Matches Orca's embedded-Chromium-per-worktree without new machinery.

Suggested roadmap

  1. Stage 1 — see the fleet: semantic state via hooks (+ fallback heuristics), state badges in trees/tabs/flipper, focus-next-blocked; session browser + resume-any; per-session cost tooltip. (items 1, 4, 5)
  2. Stage 2 — isolate & review: worktree-per-session lifecycle (create → review diff → PR/merge → archive) and the diff-comment → session loop. (items 2, 6)
  3. Stage 3 — arm the agent: MCP server (diagnostics, editor, build, screenshot); browser-pane ↔ session links. (items 3, 9)
  4. Stage 4 — orchestrate: task queue, plan-approval surface, and (if demand) compare-N-approaches à la Crystal. (items 7, 8)
